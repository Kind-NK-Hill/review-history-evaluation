# 第一批相反案例：哪些解释需要收窄

本表有目的地复查与第二批解释相关的七类既有案例，不是对第一批33次运行重新逐事件标注。L3核对保存的原审核、诊断输入与逐次输出索引；M2核对冻结的审核和新旧接口源码；L7核对封存至最终差异。其余三类复用第28版已经定位的采用与范围调查，下面明确链接这一证据层级。批次不合并估计频率。

## 1. “额外前提”不能单独决定判定

| 对照 | 已有证据与本轮核对 | 对第二批解释的约束 |
|---|---|---|
| 第一批A/B-L3：全部项可积 | 原交付需要∀n可积，共同范围允许最终可积；初始项1/x、其余及极限为0给出输入范围反例。后续修复实际增加尾部积分与原序列恢复 | 不能以“调用者总能补条件”忽略任务专有推导。第二批C-L3则已经完成尾部部分，剩余非负性和强可测性可在原输入上直接推出，两者不能同判 |
| 第一批A-M2：中心矩前提 | 原审核指出缺少原始矩→中心矩桥接；新代码确实证明E[(Xᵢ−m)⁴]≤8(c+m⁴)，公开定理接受原始矩，保留中心矩核心为辅助 | 真实修复不是删除参数文字，而是补出桥接。第二批M2三者最终均有这一桥接；A中间额外加入同分布则是另一种范围退缩 |
| 第一批L7：合理命题修正 | 相对连续性建议被单点集合反例推翻；仅在极限支撑点环境连续仍不足以保证每项复合可测，因此公开加入映射可测性具有数学理由 | “加前提”既可能缩窄一个原本成立的题，也可能修正不成立的原要求。第二批三者接受可测映射及适当环境连续，不能自动扣分 |

**M2原件。** [原审核摘录](../../../../review_history_retro_20260901/research_framework/full_workflow_eval_codesign_20260910/trajectory_analysis_20260911/case_evidence/T01-E10.txt)同时承认矩展开和尾界已完成，拒绝的是缺少原始输入桥接；[新接口及证明](../../../../review_history_retro_20260901/research_framework/full_workflow_eval_codesign_20260910/trajectory_analysis_20260911/case_evidence/T01-E11.txt)给出逐点不等式、可积性、积分比较与最终调用。两种“存在统一矩界”的条件在数学上有关，不意味着已提交代码自动提供了适用于原输入的调用。

**L3原件。** [A旧一般复审](../../team_review_v031_trajectory_v3_20260911/combined_revision_v28_20260915/verification/revision14/l3/general-v2.json)明确说非负与可测前提已经内化、密度下游可用，仍放行全项可积接口。与之对照，[第二批C调用见证](../../team_review_v031_trajectory_v3_20260911/combined_revision_v28_20260915/verification/revision23/evaluation/L3.lean)只用有序极限和可积蕴含强可测的通用事实，直接调用已有最终可积结论，没有代写尾部证明。该对照支持“检查适用输入与剩余证明责任”，不支持“参数越少越完整”。

## 2. 发现、阻断与修复是三种结果

旧L3固定代码的十二份既有诊断提供了针对这一差异的证据：

| 来源及指令（每格3次） | 明确讨论尾部遗漏 | 要求修复 | 通过 |
|---|---:|---:|---:|
| A，原指令 | 0 | 0 | 3 |
| A，追加范围核查 | 3 | 3 | 0 |
| B，原指令 | 3 | 1 | 2 |
| B，追加范围核查 | 3 | 3 | 0 |

这里的0表示回复没有明确讨论，不能推断模型内部没注意到。B原指令两份通过意见已经指出尾部推广，却将其视为可选；所以用通过率代表发现能力会混淆判断环节。A的原指令又围绕已经修复的旧问题和本就逐项可积的密度调用，未覆盖更宽输入。

[输入与逐次输出入口](../../team_review_v031_trajectory_v3_20260911/combined_revision_v28_20260915/manuscript/appendix.zh-CN.md#q4)。保存的[诊断解释](../../team_review_v031_trajectory_v3_20260911/combined_revision_v28_20260915/verification/revision23/analysis/L3_INTERPRETATION.zh-CN.md)前两节用于此表；其后关于新C-L3的旧失败解释已由共同标准修正，不沿用。A/B来源提示不同、每条件仅3次；B诊断环境不能重新构建，A引用已有构建，不能说十二次均完成独立编译。

两次另行冻结指令的修复分别用7.28和6.98分钟补齐尾部范围。它们支持“明确缺口后能够修复”；修复指令早于诊断返回，不支持“某一诊断直接导致成功”。原交付标签与修复结果分别保留。

## 3. 审核之后的时间未必是新证明

[A-L7封存至最终差异](../../team_review_v031_trajectory_v3_20260911/combined_revision_v28_20260915/verification/revision13/a-l7/sealed-candidate-to-final.diff)仅改连续映射定理的解释性注释，签名和证明体已经在封存候选中存在。续作约14.5分钟完成修正披露、审核和交付，不能写成重新构造证明。它与第二批C-L7相呼应：后者三份数学主体在移除导入行后与重新分文件的终稿相同。

但原选中交付和封存工作候选不同，不能据后者有证明而把原交付提前判完成；外层明确中止也不能解释成作者自主放弃。[原停止条件、书面反例与恢复结果](../../team_review_v031_trajectory_v3_20260911/combined_revision_v28_20260915/manuscript/appendix.zh-CN.md#r2-6)。

## 4. 委派范围与可用成果不存在一条简单对应

| 第一批既有调查 | 第二批对照 | 必须收窄的解释 |
|---|---|---|
| 较早A-L5助手有534行已构建候选，但作者收到容器外路径，未确认实际采用 | A-M2、A-M3首轮完整证明未回传；A-L5第二批首轮补丁实际到达，却因未声明依赖受阻 | 不能把所有重复委托称为同一种“交付失败”；可访问、可应用、依赖允许、数学覆盖分别核查 |
| A-H1从宽泛只读请求转到分析引理，再由另一个助手补完整反演并经外层恢复交付 | 第二批A/B-H1也有被采用的部分核、未知极限和条件反演 | 部分帮助有实际贡献，但窄委托的普遍优越性没有被识别；权限、任务范围、上下文同时不同 |
| B-M1整组停止定理委派成功，作者应用、真实构建与评审，目标源码对应 | 第二批B-L2、C-L4整组实现被采用；B-M2只收到部分支持，作者仍承担主要矩递推 | “帮助调用完成”不等于任务完成；完整委派并非必然失败，部分委派也并非必然足够 |

这三行复用[第28版已定位的协作调查](../../team_review_v031_trajectory_v3_20260911/combined_revision_v28_20260915/manuscript/appendix.zh-CN.md#r2-3)，不冒称本轮重建了第一批所有补丁。额外的B-L2恢复案例只有产物恢复被确认，采用未核实，仍保留未知。

## 5. 不能把更强要求默认为共同标准

第一批L2的相对应库接口曾被不一致评分；库中的函数版本由点态版本转换而来，两者都仍须完成不相关消项与弱大数律。H1教材核心要求标准Cauchy，任意位置尺度是额外推广。[既有范围核查](../../team_review_v031_trajectory_v3_20260911/combined_revision_v28_20260915/manuscript/appendix.zh-CN.md#r1-3)约束本轮：H1第二批不能因只证明标准分布而判不足；L5的一般测度推广与显式混合形式也应从已经完成的核心目标之后另记。

这些反例没有推翻过程比较，反而确定了比较对象：实际数学需要、任务适用范围、可被调用的证明内容，以及可验证的采用路径。它们推翻的是用审核次数、参数数量、助手范围或报错次数直接替代这些判断的做法。
