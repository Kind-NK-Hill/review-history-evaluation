# M2：证明丢失、范围退缩与冗余路线展示

本组要求相互独立、共同均值、原始四阶矩一致有界的强大数律，不要求同分布。见[M2证据](M2_EVIDENCE.zh-CN.md)与[时间区间](m2_stage_intervals.json)。官方总时间A51.17、B40.56、C22.91分钟。

## 1. 三者最终真正证明了什么？

先令Yᵢ=Xᵢ−m，从原始矩条件推出中心四阶矩的一致界；再令Sₙ为中心变量部分和。三者最终都按Sₙ₊₁=Sₙ+Yₙ递推，而非直接拆分全部四重指标。独立性使三次—一次混合积分为零，二次—二次项分解，得到E[Sₙ⁴]不超过常数乘n²。四阶Markov界随之给出P(|Sₙ/n|>ε)不超过常数乘1/(n²ε⁴)，对全部n可求和，因此第一Borel–Cantelli直接控制全序列。

找到独立积分分解定理后，仍需证明每种混合幂可积，并把函数乘法、点态幂、积分展开连起来。A第三助手、B和C均尝试过Lp乘法或Hölder指数接口；最终的重要处理是用两项四次方之和控制混合项，并结合既有四阶可积性。这里的检索后工作既含类型表示适配，也含选择更易验证的可积性证明。

## 2. A有完整早期证明，为什么还用了51分钟？

| 节点 | 可观察结果 |
|---|---|
| 第一助手，14.52分钟 | 非同分布四阶矩证明正式构建通过，候选哈希4d7174… |
| 作者，15.44分钟 | 仍见200行空草稿，哈希ee4cc3…；助手写入的产物目录未进入回传补丁 |
| 第二助手，20.91分钟 | 重建为同分布特例并构建通过，额外加入hident；随后导出失败，22.21分钟请求返回错误 |
| 第三助手，42.98分钟 | 重新完成非同分布证明，并按请求放入可回传仓库文件 |
| 作者，44.22分钟 | 实际应用并正式构建通过；随后审核采用 |

因此，A的较长运行不能概括为数学题本身需要三次求解才成功。第一轮数学工作已经完成，但结果没有送达；第二轮又同时出现范围退缩与导出失败。二者是不同事件：额外同分布使候选不符合原要求，导出失败阻断成果回传。没有记录支持作者已经看见并有意识接受这个较弱候选。

## 3. B的部分帮助有效，但主证明仍由作者补完

B助手15.76分钟传回经过编译的中心化、独立和消项支持，明确指出剩余责任。作者19.47分钟采用，之后完成可积性、矩递推、尾界及全序列收敛，到35.56分钟目标通过。这是部分成果被采用并继续推进的实例；用“帮助调用完成”替代“任务完成”会提前近20分钟判成功。

B随后补写平方子列展示。审核指出：先从全序列收敛推出平方子列，再借已知全序列结果回到结论，并没有独立完成子列到全序列的推导。这个批评对附加展示是成立的，但审核也确认此前全序列证明本身正确。因此不能称主定理存在循环论证，更不能把该审核意见自动继承为统一数学标准下的失败标签。

C协调请求事先明确允许直接全序列证明，17.53分钟完成原始条件主定理，18.69分钟完整构建。它没有加入B那段冗余展示。对照揭示的是路线要求如何影响后续行为，并不足以单独估计协调指令的因果效应。

## 4. 三章可以据此增加的解释

- 第三章：A的时间差应展示“首个已验证证明—未送达—重建—实际采用”，而非仅列助手数量；B要显示部分支持之后作者承担的矩递推工作。
- 第四章：把“不满足指定展示路线”与“未证明目标命题”分开；同分布特例则是真实限制输入范围，不能与冗余子列步骤混同。
- 第五章：追踪数学工作是否完成、是否送达、是否适用、是否采用。四者可能给出不同答案；相同的再次委托动作也可能对应完全不同原因。
