# 第二批33项主运行的公开工具记录

本目录把原始公开记录转换为可复跑、逐行可回查的工具事件；不产生失败恢复率或最终成果采用判断。

主样本严格选自 `RUN_INDEX.csv` 的33条 `main_original`，对应11组任务、A/B/C三种配置。原始终验、L3诊断审核、额外修复、工程续接和宿主任务均排除。每个角色的记录由相邻执行回执绑定到 `SOLVER_TERMINAL.json` 中的派发ID，而不是凭目录名字判定角色。

| 可观察量 | 数量 |
|---|---:|
| 主运行 | 33 |
| 角色派发／公开记录文件 | 163 |
| 不同会话 | 135 |
| 实际服务调用 | 4054 |
| 工具发现调用 | 179 |
| 请求与回执配对 | 4233／4233 |
| 容器命令调用 | 3802 |
| 容器命令回执含退出码 | 3797／3802 |

135个会话发生163次派发，来自会话继续执行。当前公开文件保存对应派发片段；同一会话内没有重复调用ID。抽取仍以会话ID和调用ID配对、去重，不把请求与回执算成两次调用。另有13份工程会话公共副本，与主样本会话没有交集，全部排除。

9次服务调用没有可解析的执行退出码，实际回执是参数无效或超范围的工具协议错误。其中容器执行5次、读取材料4次。程序保留这些原文和来源，不补造退出码，也不把它们称为数学失败。

服务进程退出码和服务内检查结果分开保存。例如协调工具返回退出码0只说明服务进程正常返回；内部构建或评审内容仍须读取 `structured_result`。同样，读取说明书返回的“error”文字不构成一次失败。运行总结果仍由共同数学验收确定，本目录没有改动通过条件。

`dispatch_result_elapsed_seconds` 是记录中的请求至回执间隔，包含等待；并行、交错任务不能由此分摊纯搜索时间。`elapsed_seconds` 仅保存回执明确给出的时间。当前主样本使用同步容器执行，没有原生 `exec_command` / `write_stdin` 续轮，故没有虚构进程连接。

入口与复跑：

- [字段说明](SCHEMA.md)：输出接口与字段含义。
- [事件数据](events.jsonl)：完整参数、回执、退出码与双向物理行来源；文件较大，可逐行读取。
- [按运行覆盖](run_coverage.csv)、[按角色覆盖](role_coverage.csv)、[逐派发覆盖](actor_coverage.json)。角色续跑独立列项；角色表不同标签可能属于同一会话，不能跨标签相加得到唯一会话数。
- [核验结果](qa.json)：样本边界、完整性、请求回执配对、时间边界、原始摘要和源文件未改动均通过。
- [源文件摘要](source_manifest.json)与[输出摘要](output_manifest.json)。

从本目录运行 `python extract_events.py`。只依赖Python标准库，不运行原始命令，不访问额外模型或网络。另运行 `python -m unittest test_extract_events.py` 检查文档中的错误词、嵌套返回、协议错误、Unicode行分隔符、重复副本和进程续轮六类计数陷阱。

记录完整仅意味着公开输入、工具调用及回执有对应证据；不代表片段边界、语义分类、恢复判断或最终采用已经验证。后续分析应在这一层证据之上独立建立并检查标注。

## 论文统计单位说明

本提取产物的tool_family=service对应4,054次实际工具调用，包括命令执行、读取产物和求助等；论文对外称“实际工具调用”，另有179次工具发现。它不同于旧研究127项内部协助/评审服务，也不同于163次角色派发或135个会话。机器字段为兼容保留，数字与调用身份未变。
